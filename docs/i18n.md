# Interface languages

Lingo supports `zh-CN` (default) and `en`. The header and dialogs provide a language switch. The choice is stored under `lingo-locale` in local storage and synchronized between tabs. Existing URLs and member-only access rules stay the same.

`components/i18n.tsx` owns the locale context, semantic document language, localized metadata and declarative UI regions. The React tree uses identical keys in both languages, so switching does not remount forms or course readers. Form values, option values, handlers and database values are never translated.

Add English interface copy to `lib/i18n/en.mjs`, using the normalized Chinese source as the key. Dynamic messages use positional slots, for example `第 {0} 页` → `Page {0}`. Use `useI18n().t()` for imperative output such as exported filenames. Wrap newly authored UI component returns in `I18nRegion`.

User-authored resource titles, descriptions, course notes, attachments, posts and personal introductions retain their original language. Put `translate="no"` on their smallest native container; keep interface labels outside that container. Do not add machine translations of stored content to the interface catalog.

Run `node --test tests/*.test.mjs` and `tsc --noEmit`. Browser checks should include language persistence, an unsaved form draft, selected filters, mobile navigation, dark mode and signed-out member gates. English search aliases in `lib/matching.mjs` resolve to the same stored interest identifiers as Chinese.
